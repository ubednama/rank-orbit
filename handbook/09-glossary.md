# 09 — Glossary

Domain terms used throughout the codebase and handbook.

| Term                   | Definition                                                                                                                                                                                                                     |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Audit**              | One run of the SEO analysis against one URL. Composed of crawler output (Lighthouse metrics, metadata, readability stats) + AI output (summary, action plan, score, rationale). Persisted as one row in the `audits` table.    |
| **Sanitization**       | Strip tracking params (`utm_*`, `fbclid`, etc.) from a URL before crawling/caching. Two URLs that differ only in tracking params should hit the same cache entry.                                                              |
| **Sanitized URL**      | The output of sanitization. The cache primary key. Both the original and sanitized URL are cached in localStorage so users don't see redundant audits.                                                                         |
| **Content hash**       | `sha256(html)`. Used to dedup AI calls — if a prior audit's `contentHash` matches, reuse the AI result without calling Gemini again. Cheaper than caching by URL because URL contents change but identical pages share a hash. |
| **AI quota**           | Per-identifier limit on AI insights. Identifier = IP for anon, userId for authenticated. Persisted in `auditUsage` table; period = `"anon"` (lifetime) or `"YYYY-MM"` (calendar month).                                        |
| **SSE**                | Server-Sent Events. HTTP streaming protocol; one-directional (server → client). Used for live audit results.                                                                                                                   |
| **sse_token**          | Single-use HMAC-signed token issued by `POST /audit/start`. Authorizes one `GET /audit/stream` connection. Replaces putting the user JWT in the URL.                                                                           |
| **CrawlResponse**      | What crawler-service returns to gateway. Includes metadata, lighthouse_metrics, technical_analysis, readability_analysis. See [libs/shared/types](../libs/shared/types/src/lib/crawler.interface.ts).                          |
| **AiCrawlResponse**    | CrawlResponse + `page_content` (the raw HTML body). Sent to ai-service for analysis.                                                                                                                                           |
| **AIResponse**         | What ai-service returns: summary, action_plan, keyword_analysis, detailed_report, seo_score, score_rationale. Does NOT include technical_analysis (see ADR 006).                                                               |
| **technical_analysis** | Derived view of Lighthouse metrics for UI rendering. `{ Performance: {value, status}, LCP: {value, status}, ... }`. Computed by crawler, owned by crawler.                                                                     |
| **Single-flight**      | Pattern: when N concurrent requests arrive for the same key, only the first executes the work; the others subscribe to its result. Implemented via Redis `SET NX` lock.                                                        |
| **Negative cache**     | Caching the _absence_ or _failure_ of a result. We cache 4xx URLs for 1h to avoid hammering broken links.                                                                                                                      |
| **Cold cache**         | Cache miss on every layer (Redis, Postgres). Triggers full audit pipeline.                                                                                                                                                     |
| **Hot cache**          | Postgres or Redis hit. SSE returns cached audit immediately.                                                                                                                                                                   |
| **DLQ**                | Dead-letter queue. BullMQ jobs that exhaust retries land in `<queue>:failed`. Periodically reviewed; not auto-replayed.                                                                                                        |
| **SSRF**               | Server-Side Request Forgery. Attacker submits a URL that causes the server to fetch a resource the attacker shouldn't be able to reach (cloud metadata, internal admin panels, RFC 1918 ranges).                               |
| **ADR**                | Architecture Decision Record. See [08-decisions.md](08-decisions.md).                                                                                                                                                          |
| **Phase**              | A versioned chunk of work with a clear "done when" criterion. See [06-phases.md](06-phases.md).                                                                                                                                |
| **v2 TODO**            | Work intentionally deferred — not bugs, but acknowledged gaps with a plan to restore. See [07-v2-todo.md](07-v2-todo.md).                                                                                                      |
| **Trust boundary**     | The line between two systems with different levels of trust (e.g., internet → gateway, gateway → crawler). Validation/auth happens _at_ boundaries.                                                                            |
| **Defense in depth**   | Validating the same thing at multiple layers (e.g., SSRF check at gateway _and_ at crawler) so a single missed check isn't catastrophic.                                                                                       |
